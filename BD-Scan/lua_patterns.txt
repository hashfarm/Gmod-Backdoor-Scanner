# Patterns for .lua files.
# Format: regex;;;[SEVERITY] ID Description;;;Optional hint
#
# The ID is the stable identifier. It is what --diff keys on and what a
# whitelist entry should reference, so descriptions can be reworded without
# invalidating baselines or whitelists. Every ID has at least one + and one -
# case in lua_patterns.test.txt, checked by the self-check and by CI.
#
# The third field is optional and is written for a server owner who does not
# read Lua: what the construct does and what separates a legitimate use from a
# malicious one. It is shown in the HTML report and stored in scan_log.json.
#
# Severity reflects what the construct means *in Garry's Mod specifically*, not
# how dangerous it sounds in general Lua.

# --- Direct code execution ---
\bRunString(?:Ex)?\s*\(|(?:^|[^\w."'])RunString(?:Ex)?\s*(?:["']|\[=*\[);;;[CRITICAL] LUA-001 Code Execution (RunString);;;Runs Lua source built at runtime. Legitimate addons almost never need this. Check where the string comes from: a literal is usually harmless, anything arriving from HTTP, a net message or a decoded blob is not.;;;tags=execution added=2025-12-03
\bCompileString\s*\(|(?:^|[^\w."'])CompileString\s*(?:["']|\[=*\[);;;[CRITICAL] LUA-002 Code Execution (CompileString);;;Turns a string into a callable function. Same question as RunString: trace the string back to its source.;;;tags=execution added=2025-12-03 ref=https://wiki.facepunch.com/gmod/Global.CompileString
\bloadstring\s*\(|(?:^|[^\w."'])loadstring\s*(?:["']|\[=*\[);;;[CRITICAL] LUA-003 Code Execution (loadstring);;;The classic Lua way to execute a string. Trace where the string comes from.;;;tags=execution added=2025-12-03
(?:^|[^\w.:"'])load\s*\((?!\s*[A-Za-z]+\s+[A-Za-z]);;;[CRITICAL] LUA-188 Code Execution (load);;;Loads a chunk of Lua from a string or a reader function and returns it ready to run. Garry's Mod keeps this next to loadstring, and a backdoor written to slip past a scanner built around loadstring uses it instead -- one sample in the corpus picks it deliberately, falling back to loadstring only when load is missing. Trace where the chunk comes from: a constant is usually harmless, anything arriving from HTTP, a net message or a decoded blob is not.;;;tags=execution added=2026-09-19
\bBroadcastLua\s*\(\s*(?!(?:string\.format\s*\(\s*)?["'\[])[^\s)];;;[CRITICAL] LUA-004 Server Code Broadcast With A Computed String;;;Runs Lua on every connected player from source assembled at runtime. A literal string, or a literal string.format template, is routine gamemode work; a variable means whoever controls that variable controls every client.;;;tags=execution added=2025-12-03 ref=https://wiki.facepunch.com/gmod/Global.BroadcastLua
\bSendLua\s*\(\s*(?!(?:string\.format\s*\(\s*)?["'\[])[^\s)];;;[CRITICAL] LUA-005 Client Code Execution With A Computed String;;;Runs Lua on one client from a string built at runtime. Garry's Mod's own gamemodes call SendLua with literal strings and literal format templates constantly, so a computed argument is the part that matters.;;;tags=execution added=2025-12-03 ref=https://wiki.facepunch.com/gmod/Player:SendLua
\b(?:SendLua|BroadcastLua)\s*\(\s*(?:string\.format\s*\(\s*)?["'\[];;;[LOW] LUA-009 Client Code Execution With A Literal;;;Sends a fixed piece of Lua to clients, possibly with values filled into a fixed template. Common in gamemodes and tools; worth reading only if the literal itself does something unexpected, or if a %s slot takes player-supplied text.;;;added=2026-09-16 tags=execution
\bCompileFile\s*\(|(?:^|[^\w."'])CompileFile\s*(?:["']|\[=*\[);;;[HIGH] LUA-006 File Compilation;;;Compiles a Lua file from disk. Only dangerous if the file itself was planted, so check what path is passed and whether anything writes to it.;;;tags=execution added=2025-12-03 ref=https://wiki.facepunch.com/gmod/Global.CompileFile
[(,]\s*(?:RunString(?:Ex)?|CompileString|CompileFile|BroadcastLua|SendLua)\s*[,)]|\b(?!(?:RunString(?:Ex)?|CompileString|CompileFile|BroadcastLua|SendLua)\s*=)\w+\s*=\s*(?:RunString(?:Ex)?|CompileString|CompileFile|BroadcastLua|SendLua)\b(?!\s*[("']);;;[CRITICAL] LUA-007 Execution Function Passed Around As A Value;;;An execution function is handed to something else instead of being called: passed straight to http.Fetch as its callback, or stored under a different name. That is deliberate indirection and a common way to stay under a scanner's radar. Caching a function under its own name, as in local RunString = RunString, is a speed trick every Lua library uses and is not reported.;;;tags=execution added=2025-12-03
\b(?:(?:RunString(?:Ex)?|CompileString|loadstring)\s*\([\s\S]{0,200}?\bfile\.Read\s*\(|file\.Read\s*\([\s\S]{0,200}?\b(?:RunString(?:Ex)?|CompileString|loadstring)\s*\();;;[CRITICAL] LUA-008 File Contents Executed as Code;;;A file is read off disk and its contents are executed. When the path points at a material, sound or texture, this is the loader half of a backdoor whose payload is parked in an asset file where nobody looks.;;;tags=execution added=2025-12-03 ref=https://wiki.facepunch.com/gmod/file.Read

# --- Remote or deferred code execution ---
\b(?:http\.(?:Fetch|Post)|HTTP)\s*\([\s\S]{0,600}?\b(?:RunString(?:Ex)?|CompileString|loadstring)\b;;;[CRITICAL] LUA-010 Remote Code Execution via HTTP;;;Code is downloaded and then executed. This is the single most common backdoor shape. Look at the URL: whoever controls it controls your server.;;;tags=execution,remote added=2025-12-03
\btimer\.(?:Simple|Create)\s*\([\s\S]{0,400}?\b(?:RunString(?:Ex)?|CompileString)\b;;;[CRITICAL] LUA-011 Delayed Code Execution via Timer;;;Execution is delayed or repeated on a timer, which hides it from anyone watching startup. A repeating timer around code execution is a beacon.;;;tags=execution,remote added=2025-12-03
\bhook\.Add\s*\([\s\S]{0,400}?\b(?:RunString(?:Ex)?|CompileString)\b;;;[CRITICAL] LUA-012 Hook with Code Execution;;;Code execution wired into a game event, so it fires on player join, spawn or similar rather than at load.;;;tags=execution,remote added=2025-12-03 ref=https://wiki.facepunch.com/gmod/hook.Add
\bnet\.Receive\s*\([\s\S]{0,400}?\b(?:RunString(?:Ex)?|CompileString)\b;;;[CRITICAL] LUA-013 Network Receive with Code Execution;;;Executes code arriving from a client. If the handler does not verify the sender is an admin, any player can run Lua on your server.;;;tags=execution,remote added=2025-12-03 ref=https://wiki.facepunch.com/gmod/net.Receive
\bconcommand\.Add\s*\([\s\S]{0,400}?\b(?:RunString(?:Ex)?|CompileString)\b;;;[CRITICAL] LUA-014 Console Command with Code Execution;;;Registers a console command that executes code. Check whether the handler verifies who is calling it.;;;tags=execution,remote added=2025-12-03 ref=https://wiki.facepunch.com/gmod/concommand.Add
\bcoroutine\.(?:wrap|create)\s*\(\s*function[\s\S]{0,400}?\b(?:RunString(?:Ex)?|CompileString)\b;;;[CRITICAL] LUA-015 Coroutine with Code Execution;;;Execution wrapped in a coroutine, which obscures the call stack.;;;tags=execution,remote added=2025-12-03
\butil\.JSONToTable[\s\S]{0,400}?\b(?:RunString(?:Ex)?|CompileString)\b;;;[CRITICAL] LUA-016 JSON Payload Passed to Code Execution;;;A JSON response is parsed and part of it is executed as code. The remote side decides what runs.;;;tags=execution,remote added=2025-12-03
\b(?:util\.Base64Decode[\s\S]{0,200}?\b(?:RunString(?:Ex)?|CompileString)\b|(?:RunString(?:Ex)?|CompileString)\s*\([\s\S]{0,200}?util\.Base64Decode);;;[CRITICAL] LUA-017 Base64-Decoded Payload Executed;;;Code is Base64-encoded and then executed. Encoding serves no purpose here except to make the payload unreadable.;;;tags=execution,remote added=2025-12-03
\bconcommand\.Add\s*\([\s\S]{0,400}?\bhttp\.(?:Fetch|Post)\b;;;[HIGH] LUA-018 Console Command Triggering HTTP Request;;;A console command that talks to a remote server. Check the URL and what data is sent.;;;tags=execution,remote added=2025-12-03 ref=https://wiki.facepunch.com/gmod/concommand.Add
\btimer\.(?:Simple|Create)\s*\([\s\S]{0,400}?\bhttp\.(?:Fetch|Post)\b;;;[MEDIUM] LUA-019 Delayed or Repeating HTTP Request;;;Often a harmless update or statistics check. Confirm the URL belongs to the addon author and look at what is sent.;;;tags=execution,remote added=2025-12-03

# --- Environment, registry and global table ---
\bgetfenv\s*\(;;;[HIGH] LUA-020 Environment Access (getfenv);;;Reads the variable environment of a function. Used legitimately by sandboxing and module loaders, and by backdoors to reach globals that were hidden from them.;;;tags=environment added=2025-12-03 ref=https://wiki.facepunch.com/gmod/Global.getfenv
\bsetfenv\s*\(;;;[HIGH] LUA-021 Environment Modification (setfenv);;;Replaces a function's environment. Legitimate in sandboxes; also how code hides what it touches.;;;tags=environment added=2025-12-03 ref=https://wiki.facepunch.com/gmod/Global.setfenv
\bdebug\.getregistry\s*\(;;;[MEDIUM] LUA-022 Debug Registry Access;;;Very common: most addons use it to reach a metatable. Only interesting in combination with other findings in the same file.;;;tags=environment added=2025-12-03 ref=https://wiki.facepunch.com/gmod/debug.getregistry
\bdebug\.setlocal\s*\(;;;[HIGH] LUA-023 Debug Local Modification;;;Rewrites a local variable inside a running function. Almost never legitimate in an addon.;;;tags=environment added=2025-12-03 ref=https://wiki.facepunch.com/gmod/debug.setlocal
\bdebug\.setupvalue\s*\(;;;[HIGH] LUA-024 Debug Upvalue Modification;;;Rewrites a captured variable inside an existing function, which is how a permission check in someone else's addon gets neutered without touching their file.;;;tags=environment added=2025-12-03 ref=https://wiki.facepunch.com/gmod/debug.setupvalue
\bdebug\.getupvalue\s*\(;;;[HIGH] LUA-025 Debug Upvalue Read (Closure Inspection);;;Reads captured variables out of another addon's functions. Paired with setupvalue this is closure hijacking.;;;tags=environment added=2025-12-03 ref=https://wiki.facepunch.com/gmod/debug.getupvalue
\bdebug\.sethook\s*\(;;;[HIGH] LUA-026 Debug Hook Set;;;Installs a callback that fires on every Lua instruction. Legitimate in profilers, otherwise a red flag.;;;tags=environment added=2025-12-03 ref=https://wiki.facepunch.com/gmod/debug.sethook
_G\s*\[[^\]]{1,200}\]\s*=\s*function;;;[HIGH] LUA-027 Dynamic Global Function Assignment;;;Defines a global function under a computed name. Module loaders do this; so does code that wants its entry point to be hard to grep for.;;;tags=environment added=2025-12-03
(?:_G|_R|_ENV|getfenv\s*\(\s*[^)]{0,20}\))\s*\[\s*["'](?:RunString|RunStringEx|CompileString|loadstring|CompileFile|BroadcastLua|SendLua|getfenv|setfenv|require|pcall|RunConsoleCommand)["']\s*\];;;[CRITICAL] LUA-028 Dangerous Function via Global Table Lookup;;;Reaches a dangerous function through the global table instead of naming it directly. There is no legitimate reason to write it this way; the point is to defeat a text search.;;;tags=environment added=2025-12-03
(?:_G|_R|_ENV|getfenv\s*\(\s*[^)]{0,20}\))\s*\[[^"'\]]{1,200}\];;;[MEDIUM] LUA-029 Dynamic Global/Registry Access (Variable Key);;;A global is looked up by a variable name, so what is accessed is not visible in the source. Common in module loaders, also used to hide the target.;;;tags=environment added=2025-12-03
\brawset\s*\(\s*_G\s*,;;;[HIGH] LUA-030 Raw Global Table Modification;;;Writes a global while bypassing any metatable protection a gamemode installed.;;;tags=environment added=2025-12-03 ref=https://wiki.facepunch.com/gmod/Global.rawset
(?:_G|_R|_ENV|getfenv\s*\(\s*[^)]{0,20}\))\s*\[[^"'\]]{1,200}\]\s*\(;;;[HIGH] LUA-031 Dynamic Global Called By A Variable Key;;;A global is looked up by a name held in a variable and then called straight away. Which function runs is decided at runtime and appears nowhere in the source, which is the point: the name of the dangerous call is never written down. Factory code does this legitimately, so read what the variable holds. Assembled from pieces, or arriving over the network, makes this an execution primitive.;;;tags=obfuscation,execution added=2026-09-16
\(\s*["'][^"'\n]{2,}["']\s*\)\s*:\s*(?:gsub|sub|reverse)\s*\(;;;[MEDIUM] LUA-032 String Literal Rewritten In Place;;;A string constant rewritten on the spot, without ever being stored in a variable. Only the rewriting methods count here: ("..."):format() and ("..."):rep() are everyday Lua and are not reported. Substituting into or slicing a constant is how a name is kept out of the file that uses it. Work out what it evaluates to.;;;tags=obfuscation added=2026-09-16

# --- Privilege escalation and admin takeover ---
:SetUserGroup\s*\(\s*["'](?:superadmin|admin)["']\s*\);;;[CRITICAL] LUA-040 Setting User to Admin/Superadmin;;;Grants admin rights from code. Check which player this applies to and what condition guards it. A hardcoded SteamID here is a backdoor.;;;tags=privilege added=2025-12-03
(?:\bIs(?:Super)?Admin\s*=\s*function|\bfunction\s+\w+\s*[:.]\s*Is(?:Super)?Admin\s*\();;;[HIGH] LUA-041 Admin Check Overridden;;;Redefines the function the whole server uses to decide who is an admin. Some gamemodes legitimately do this; read the body and check it cannot return true for an attacker.;;;tags=privilege added=2025-12-03
["']STEAM_[0-5]:[01]:[0-9]{4,}["'];;;[MEDIUM] LUA-042 Hardcoded SteamID;;;Very common in owner configuration. Check whose ID it is, and whether it appears next to a permission grant.;;;tags=privilege added=2025-12-03
\bucl\.add(?:User|Group)\s*\(;;;[MEDIUM] LUA-043 Direct ULib Permission Change;;;Changes ULX permissions from code instead of through the admin menu. ULib and ULX do this constantly in their own files, which is why this is not HIGH; in an unrelated addon it is worth reading.;;;tags=privilege added=2025-12-03
\b(?:RunConsoleCommand|game\.ConsoleCommand)\s*\(\s*["'](?:sv_allowcslua|rcon_password|ulx adduser|ulx addgroup);;;[CRITICAL] LUA-044 Security-Relevant Console Command;;;Disables a protection or grants permissions from code. sv_allowcslua 1 in particular lets any client run Lua on your server.;;;tags=privilege added=2025-12-03
\b(?:RunConsoleCommand|game\.ConsoleCommand)\s*\(\s*["'](?:sv_cheats|sv_password|sv_kickerrornum);;;[HIGH] LUA-181 Server Setting Changed From Code;;;Changes a server setting that affects everyone. Demo and recording tools legitimately toggle sv_cheats; check that the code around it explains why.;;;added=2026-09-16 tags=privilege
\b(?:RunConsoleCommand|game\.ConsoleCommand)\s*\(\s*(?!["'\[])[^\s)];;;[MEDIUM] LUA-045 Console Command Built At Runtime;;;The command name is a variable rather than something you can read. Every addon runs console commands, so only the ones whose name is assembled at runtime say anything; look at where the string comes from.;;;tags=privilege added=2025-12-03
\bsv_allowcslua\b;;;[HIGH] LUA-046 CSLua Setting Referenced;;;This convar controls whether clients may run their own Lua. If something sets it to 1, every player can execute code.;;;tags=privilege added=2025-12-03
\brcon_password\b;;;[HIGH] LUA-047 RCON Password Referenced;;;Addons have no reason to read the RCON password. If it is being read, find out where it goes.;;;tags=privilege added=2025-12-03
:ConCommand\s*\(\s*["']\s*(?:connect|retry|disconnect|quit|exit|unbindall|kill)\b;;;[HIGH] LUA-048 Forced Client Command (Redirect/Disconnect);;;Forces a command on a player's own client, for example connecting them to another server. This is how player-stealing addons work, and also how a server network's hub sends people between its own servers. Look at what address it sends them to and what triggers it.;;;tags=privilege added=2025-12-03

\bstring\.format\s*\(\s*["'](?:%c){3,};;;[HIGH] LUA-057 CharCode Obfuscation via string.format;;;Another way to build text from character codes rather than writing it out.;;;tags=obfuscation added=2025-12-03 ref=https://wiki.facepunch.com/gmod/string.format

\bbit\.bxor[\s\S]{0,150}?string\.char;;;[HIGH] LUA-059 XOR Decoding Loop;;;XOR plus character building is a decryption routine. Whatever it produces was meant not to be read.;;;tags=obfuscation added=2025-12-03
